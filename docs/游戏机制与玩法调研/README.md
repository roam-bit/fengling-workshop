# 凤翎工坊：游戏机制与玩法调研

更新时间：2026-07-03

## 结论

凤翎工坊的产品不是《07号调查员》这一个游戏，而是让小说作者制作互动叙事游戏的平台。《07号调查员》只能作为平台的示例项目和验收模板。

平台需要分成两个互相独立、但能组合的层次：

1. **游戏机制层**：作者配置触发、条件、状态和动作。
2. **游戏玩法层**：平台把一组机制包装成可直接使用的玩法模板，例如调查推理、钥匙解谜、关系对话和倒计时生存。

只做机制编辑器，作者仍然不知道如何把机制组合成“好玩的循环”；只做一个示例游戏，则无法证明这是创作平台。两层都必须存在。

## 当前工程判断

现有运行时已经能执行：

- 分支对话和分支结果；
- 条件对话页；
- 开关状态、访问记录、道具和线索；
- 自动、进入区域、离开区域等触发；
- 文本、选择、设置状态、条件分支、增加线索、给予道具、传送、特效、等待等动作；
- 道具门、章节解锁和本地存档。

缺口主要在创作者侧：这些能力大多埋在 `chapters.json`，没有形成统一、可视、可校验的机制编辑体验，也没有被包装成作者可以直接套用的玩法模板。

## 决策摘要

- 保留 Phaser 作为 Web 运行时，不替换引擎。
- 首版采用 GB Studio 式事件卡，不使用 Blockly 积木作为默认界面。
- 规则采用 GDevelop 的“触发 + 条件 + 动作”语义。
- 首版优先制作“调查推理玩法包”，因为它能直接复用现有工程能力。
- 所有开源项目先借鉴交互和数据模型；若复用代码，必须逐项进行许可证和依赖审查。
