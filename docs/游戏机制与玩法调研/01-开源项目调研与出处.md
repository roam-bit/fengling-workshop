# 开源项目调研与出处

调研日期：2026-07-03

本报告只记录官方仓库或官方文档。星标数量会随时间变化，因此只用于判断社区规模，不作为产品决策的唯一依据。

## 候选项目对比

| 项目 | 许可证 / 社区规模 | 值得借鉴 | 不应照搬 | 采用判断 |
|---|---|---|---|---|
| [GB Studio](https://github.com/chrismaltby/gb-studio) | MIT，约 9.3k stars | 选中场景、角色或触发区后配置顺序事件卡；事件搜索、复制、禁用、分组；可导出 Web | Game Boy 规格限制及其 C 运行时 | **首要 UI 参考** |
| [GDevelop](https://github.com/4ian/GDevelop) | MIT，约 24k stars | 无代码事件系统、条件与动作、变量、可复用 Behavior | 完整引擎体量过大，内部模型与现有工程耦合方式不同 | **首要规则语义参考** |
| [Twine](https://github.com/klembot/twinejs) | GPL-3.0，约 2.8k stars | 故事地图、节点连线、断链提示、自动创建目标节点 | GPL 编辑器代码不能随意并入非 GPL 产品；宏语言对普通作者仍像代码 | 只借鉴宏观故事图交互 |
| [Bitsy](https://github.com/le-doux/bitsy) | MIT，约 1.1k stars | 就地编辑 NPC、物件、出口；锁门、拾取物和结局模板 | 16×16 像素世界和小体量项目限制 | 借鉴“领域模板”设计 |
| [Yarn Spinner](https://github.com/YarnSpinnerTool/YarnSpinner) | MIT，约 2.7k stars | 对白、选项、变量和游戏命令分离；预览时观察条件和变量 | 主实现是 C#，文本脚本并非目标作者需要的零代码界面 | 借鉴对话与动作解耦、预览调试 |
| [Ink](https://github.com/inkle/ink) / [Inky](https://github.com/inkle/inky) | MIT | 即时编译、边写边玩、错误定位、状态序列化 | 符号化 DSL 学习成本高，不是完整游戏机制编辑器 | 借鉴即时试玩和错误诊断 |
| [Blockly](https://github.com/RaspberryPiFoundation/blockly) | Apache-2.0，约 13.4k stars | 可嵌入 Web 的可视编程库，自定义块和序列化成熟 | 积木连接仍要求编程思维，长规则阅读效率低 | 后续高级模式候选，不进入首版 |
| [Phaser](https://github.com/phaserjs/phaser) | MIT，约 40k stars | WebGL/Canvas 渲染、输入、碰撞、地图、桌面与移动 Web | 本身没有面向小说作者的无代码机制编辑器 | 继续作为运行时 |

## 官方功能出处

### GB Studio

- [官方仓库](https://github.com/chrismaltby/gb-studio)
- [脚本事件文档](https://www.gbstudio.dev/docs/scripting/)
- [可视化 Script Values](https://www.gbstudio.dev/docs/scripting/script-values/)
- [Web 构建](https://www.gbstudio.dev/docs/build/)

可借鉴结论：创作者最容易理解的微观流程是“选中对象 → 选择触发时机 → 添加事件卡 → 即时试玩”。事件卡比自由 JSON 和通用编程积木更适合首版。

### GDevelop

- [官方仓库](https://github.com/4ian/GDevelop)
- [事件系统介绍](https://gdevelop.io/page/how-to-make-a-game-without-coding)
- [官方扩展仓库](https://github.com/GDevelopApp/GDevelop-extensions)

可借鉴结论：统一规则模型应是“当事件发生，如果条件成立，则按顺序执行动作”。变量、对象和场景必须有明确作用域；玩法能力通过可复用模板提供。

### Twine

- [官方仓库](https://github.com/klembot/twinejs)
- [故事地图导航](https://twinery.org/reference/en/editing-stories/navigating.html)
- [节点链接](https://twinery.org/reference/en/editing-stories/linking-passages.html)

可借鉴结论：宏观关系图适合检查场景、对话和结局是否连通，但不适合承载每一条细粒度机制规则。

### Bitsy

- [官方仓库](https://github.com/le-doux/bitsy)
- [对话编辑器](https://make.bitsy.org/docs/tools/dialog/)
- [分支列表](https://make.bitsy.org/docs/tools/dialog/lists/)
- [出口、结局与锁](https://make.bitsy.org/docs/tools/exitsandendings/)

可借鉴结论：作者需要的不是一张空白编程画布，而是“需要钥匙的门”“首次对话”“拾取线索”等带默认值的领域模板。

### Yarn Spinner、Ink 与 Blockly

- [Yarn Spinner 脚本基础](https://docs.yarnspinner.dev/write-yarn-scripts/scripting-fundamentals)
- [Yarn Spinner 对话预览](https://docs.yarnspinner.dev/write-yarn-scripts/yarn-spinner-editor/previewing-your-dialogue)
- [Ink 写作指南](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md)
- [Inky 编辑器](https://github.com/inkle/inky)
- [Blockly 官方仓库](https://github.com/RaspberryPiFoundation/blockly)

可借鉴结论：试玩器必须能够查看和修改状态、定位错误，并从指定位置开始；高级用户以后可以选择更接近表达式树或积木的界面。

## 许可证边界

- MIT、BSD、Apache-2.0 项目允许在满足许可证要求时复用代码，但仍要保留版权和许可证声明，并核对第三方依赖。
- Twine 编辑器采用 GPL-3.0。当前方案只借鉴交互思想，不复制或链接其编辑器代码。
- Phaser Editor 属于商业产品，不能当作可复制的开源代码来源。
- 本轮没有复制上述项目代码，只整理了产品模式、数据模型和官方出处。

## 最终采用组合

```text
宏观故事关系        ← Twine
对象事件卡 UI       ← GB Studio + Bitsy
触发/条件/动作语义  ← GDevelop
即时试玩与错误定位  ← Yarn Spinner + Ink
Web 游戏执行        ← 现有 Phaser 运行时
高级可视编程        ← Blockly（后续可选）
```
