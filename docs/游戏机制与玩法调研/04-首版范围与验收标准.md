# 首版范围与验收标准

## 1. 建议实施范围

首版不是做完所有游戏类型，而是跑通“作者创建机制 → 玩家形成玩法闭环 → 作者能调试”的最小完整产品。

### 模块一：项目资源库

- 道具；
- 线索；
- 开关和计数器；
- 目标；
- 结局。

### 模块二：机制卡编辑器

- 绑定场景、区域、NPC、物件或出口；
- 触发、条件、动作；
- 动作排序；
- 一次性规则；
- 启用、禁用、复制、删除。

### 模块三：三个机制模板

1. 拾取道具或线索；
2. 需要道具的门；
3. 首次/再次对话。

### 模块四：一个玩法模板

“调查推理”模板：案件目标、线索收集、线索门槛、推断和结局。

### 模块五：试玩调试器

- 从当前位置试玩；
- 状态面板；
- 规则触发日志；
- 临时改状态；
- 重置进度；
- 引用和断链错误提示。

## 2. 平台能力验收

1. 作者全程不打开 `chapters.json`，不输入内部 ID。
2. 作者能创建、修改、删除机制，保存并刷新后结果不丢失。
3. 触发区域可以在地图上创建、拖动和调整大小。
4. 资源引用通过下拉搜索完成，不能引用不存在的资源。
5. 删除被引用资源时，编辑器立即标出所有受影响位置。
6. 作者能在 3 分钟内配置“获得密卡 → 开门 → 获得线索”。
7. 作者能配置 NPC 首次与再次对话，并在试玩中验证状态切换。
8. 作者能用调查推理模板替换角色、线索和结局内容，形成新案例。
9. 试玩器显示当前道具、线索、目标、变量和规则触发记录。
10. 一键重置后，所有一次性触发、道具、线索和变量恢复初始值。

## 3. 玩家玩法验收

1. 玩家进入示例后能在 30 秒内知道当前调查目标。
2. 玩家可以通过空间探索获得密卡，而不是由系统自动发放。
3. 没有密卡时，气密门明确说明缺少什么；有密卡时执行不同结果。
4. 取得线索后，调查日志立即更新并解释线索来源。
5. 至少一个对话选项由线索或状态解锁。
6. 玩家需要完成一次线索组合或推断，而不是仅收集全部卡片。
7. 推断结果会改变角色对话、场景状态或章节可达性。
8. 至少存在两个由玩家选择和状态共同决定的结果。
9. 桌面和手机浏览器中的规则结果一致。
10. 完整闭环可以在 8—12 分钟内当面演示完成。

## 4. 保存和发布前自动检查

- 重复资源 ID；
- 缺失资源、对象或场景引用；
- 无法获得的关键道具；
- 没有默认页的条件对话；
- 无入口或无出口节点；
- 永远不成立的条件；
- 自动触发死循环；
- 没有可达结局；
- 移动端无法触发的交互。

## 5. 明确不进入首版

- 战斗和技能树；
- 装备、掉落和经济系统；
- 联机或多人协作玩法；
- 完整 Blockly 高级编程模式；
- 替换 Phaser；
- 玩法模板市场；
- 未经确认的公网发布。

## 6. 完成定义

只有同时满足以下两项，首版才算完成：

1. 《07号调查员》作为玩家作品，存在可观察、可决策、有后果的调查玩法闭环。
2. 作者能够在凤翎工坊中不写代码地复刻这条闭环，而不是由开发者手改 JSON。
