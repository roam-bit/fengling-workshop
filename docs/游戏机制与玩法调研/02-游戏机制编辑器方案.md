# 游戏机制编辑器方案

## 1. 产品目标

让不写代码的小说作者通过自然句和事件卡，定义“什么时候、满足什么条件、发生什么事情”，并能立即试玩和检查结果。

机制编辑器不是另一个通用游戏引擎。它应当优先服务互动小说、探索叙事、推理解谜和角色关系等内容型玩法。

## 2. 统一机制模型

每条机制固定由四部分组成：

```text
归属对象 + 触发时机 + 可选条件 + 顺序动作
```

示例：

```text
归属：气密门
当：玩家与气密门互动
如果：背包中有“值守密卡”
那么：显示文字 → 打开气密门 → 增加“手写标签”线索
仅执行一次：是
```

建议的内部视图模型：

```json
{
  "id": "unlock_airlock",
  "name": "使用密卡打开气密门",
  "owner": { "kind": "prop", "refId": "airlock_gate" },
  "trigger": { "type": "interact" },
  "conditions": [
    { "type": "hasItem", "refId": "keycard_belt" }
  ],
  "actions": [
    { "type": "text", "content": "密卡贴上去，红灯转绿。" },
    { "type": "addClue", "refId": "clue_airlock" }
  ],
  "once": true
}
```

这只是内部模型。普通作者界面不得要求填写 JSON 或内部 ID。

## 3. 一等资源

以下内容必须在项目资源库中显式创建和引用，不能只靠约定名称的变量：

- 道具：名称、说明、图标、是否可堆叠、是否消耗。
- 线索：名称、详情、来源、已读状态、所属案件。
- 状态：开关、计数器、文本、枚举、关系值。
- 目标：开始条件、完成条件、失败条件、显示文案。
- 结局：类型、解锁条件、展示内容、后续跳转。

## 4. 首版触发、条件和动作目录

### 触发

- 进入场景；
- 进入或离开区域；
- 与 NPC 对话；
- 点击或调查物件；
- 选择对话选项；
- 获得道具或线索；
- 状态发生变化。

### 条件

- 是否拥有某道具；
- 是否发现某线索；
- 开关是否开启；
- 数值比较；
- 是否访问场景；
- 是否完成目标；
- 全部、任一、非的条件组合。

### 动作

- 显示叙述或对白；
- 开始指定对话；
- 设置或增减状态；
- 给予或移除道具；
- 增加线索；
- 显示、隐藏或启用物件；
- 传送到场景；
- 解锁章节、目标或结局；
- 播放特效或声音；
- 等待。

## 5. 编辑界面

### 对象层

地图中选中 NPC、物件、出口或触发区域，右侧 Inspector 出现“机制”页签。

### 事件卡层

每条机制显示成可折叠事件卡：

```text
当 [玩家进入该区域] 时
如果 [线索：雾的边线从未移动] [尚未发现]
那么
  1. [显示文字] 雾贴着栏的另一侧……
  2. [增加线索] 雾的边线从未移动
[仅执行一次 ✓]
```

事件卡支持搜索、复制、排序、禁用、删除和转换为可复用模板。

### 宏观层

故事图只显示场景、主要对话、目标和结局之间的关系，用于检查断链；不在图上展示每一条动作，避免关系图失控。

### 试玩调试层

- 从当前场景、NPC 或对话节点开始；
- 查看道具、线索、状态和当前目标；
- 查看本次触发了哪条规则、哪些条件未满足；
- 临时修改变量以测试分支；
- 一键清空试玩状态；
- 刷新后回到原试玩位置。

## 6. 与现有工程的映射

| 平台概念 | 现有数据或运行能力 | 当前缺口 |
|---|---|---|
| 场景/区域机制 | `chapter.triggers` | 编辑 UI、区域可视化 |
| 物件互动 | `prop.actions`、`givesItemId`、`requiresItem` | 统一事件卡和资源选择器 |
| 条件对话 | `dialogPages[].conditions` | 对话页面和条件编辑 UI |
| 对话动作 | 对话节点 `do` | 动作卡 UI |
| 道具 | 本地背包及物件给予/校验 | 项目级道具定义库 |
| 线索 | `chapter.clues`、`addClue` | 项目级线索定义库和引用检查 |
| 状态 | flags、visited、trigger done | 状态定义、类型和调试器 |
| 章节门槛 | `locked`、`requires` | 可视化条件与解释 |
| 动作解释器 | 现有九类动作 | 无代码配置、错误校验 |

首版应优先做适配层，将编辑器模型编译回现有 JSON；不先更换 Phaser，不重写运行时。

## 7. 保存前校验

- 引用的 NPC、场景、道具、线索或状态不存在；
- 资源 ID 重复；
- 对话没有默认分支；
- 节点或场景断链；
- 条件类型不兼容；
- 状态只写不读；
- 关键道具无法获得；
- 自动规则互相触发形成死循环；
- 所有结局均不可达。
